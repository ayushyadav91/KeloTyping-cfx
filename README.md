# KeloTyping — Backend (MVC structure, MongoDB + UUID)

Node.js + Express + MongoDB backend using a classic `*.controller.ts` / `*.model.ts` / `*.route.ts` MVC naming convention, with **UUID primary keys** (via the `uuid` package) instead of Mongo's default ObjectId. Handles user authentication (local + Google OAuth) and solo typing-test results.

> Note: the real-time multiplayer/Socket.IO race layer has been removed from this version — this is auth + solo results only.

## Why UUID instead of ObjectId?
Every document's `_id` is a UUID v4 string, generated by Mongoose via the `uuid` package, instead of Mongo's default 12-byte ObjectId — matching a `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`-style schema field-for-field. Foreign keys (`userId`) are UUID strings referencing another collection's `_id`, enforced at the application layer since MongoDB has no native FK constraints.

## Setup
```bash
cd server
npm install
cp .env.example .env    # set MONGO_URI, JWT_SECRET, and GOOGLE_CLIENT_ID
npm run dev               # tsx watch, http://localhost:3000
```

Production:
```bash
npm run build
npm start
```

## Environment variables
| Variable | Required | Description |
|---|---|---|
| `PORT` | No | default `3000` |
| `NODE_ENV` | No | development / production / test |
| `MONGO_URI` | **Yes** | MongoDB connection string |
| `JWT_SECRET` | **Yes** | secret for signing JWTs |
| `JWT_EXPIRES_IN` | No | default `7d` |
| `CLIENT_URL` | No | frontend origin for CORS |
| `GOOGLE_CLIENT_ID` | Only for `/api/auth/google` | from Google Cloud Console → Credentials |

## REST API

### Auth — `/api/auth`
| Method | Route | Access | Body |
|---|---|---|---|
| POST | `/register` | Public | `{ username, email, password }` |
| POST | `/login` | Public | `{ email, password }` |
| POST | `/google` | Public | `{ idToken }` |
| GET | `/me` | Private | — |

**Google OAuth flow:** frontend uses Google Identity Services to get an `idToken`, sends it to `/api/auth/google`. Backend verifies it via `google-auth-library`, finds-or-creates the user (linking by email if a local account already exists), and returns the same JWT shape as register/login.

### Results — `/api/results`
| Method | Route | Access | Body |
|---|---|---|---|
| POST | `/` | Private | `{ wpm, accuracy, errors?, totalTyped, duration? }` |
| GET | `/me` | Private | — |
| GET | `/leaderboard?limit=10` | Public | — |

### Health
`GET /api/health` → `{ success: true, message: "API is running" }`

## Auth flow
1. `POST /api/auth/register`, `/login`, or `/google` → returns a signed JWT.
2. Client stores the token, sends it as `Authorization: Bearer <token>` on subsequent requests.
3. `auth.middleware.ts`'s `protect` verifies the token and attaches the user to `req.user` on every private route.

## Type safety
Builds clean under `tsc --strict`, including `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess`.
